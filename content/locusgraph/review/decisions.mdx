# Approve or reject

A finding in the inbox is waiting on exactly one decision.

```typescript
await client.approveFinding("fnd_…");   // it becomes a memory
await client.rejectFinding("fnd_…");    // it does not
```

Both return the finding's id and its new status.

## Approving

```typescript
const { id, status } = await client.approveFinding("fnd_…");
// status: "promoted"
```

The statement becomes a memory, filed under the `context_id` the finding named. Everything the graph is asked afterwards can reach it.

## Editing first

The distilled statement is usually right and occasionally nearly right. Fix it as you approve:

```typescript
await client.approveFinding("fnd_…", {
  statement: "no production deploys after 15:00 local on Fridays",
});
// status: "edited_promoted"
```

The outcome is a separate status, `edited_promoted`, not `promoted`, so a reviewer correcting most of what arrives is visible rather than buried.

<Callout tone="note" title="Edit rather than reject-and-rewrite">
  Rejecting a finding and storing your own version with `storeEvent` gets the same memory into the
  graph, and loses the thread back to the observation it came from. Editing keeps it.
</Callout>

## Rejecting

```typescript
const { status } = await client.rejectFinding("fnd_…");
// status: "rejected"
```

Nothing is stored. The finding stays in the record as rejected: it does not vanish, and it will not come back to the inbox.

## The statuses

| Status | Meaning |
| --- | --- |
| `pending` | Waiting on a decision |
| `promoted` | Approved as written |
| `edited_promoted` | Approved after a reviewer changed the statement |
| `rejected` | Turned down. Nothing stored |

## Reversals

A finding with a non-empty `contradicts` supersedes something already in the graph. Approving it is not additive: it changes what the graph will say next time it is asked.

Read the statement and the contexts it contradicts together before deciding. Rejecting a true reversal leaves the graph confidently wrong, which is worse than the gap that rejecting a new fact leaves.

## Wiring a review UI

```typescript
const { findings } = await client.awarenessInbox("acme");

for (const finding of findings) {
  const decision = await askAHuman(finding);   // your UI

  if (decision.action === "approve") {
    await client.approveFinding(finding.id, decision.statement ? { statement: decision.statement } : undefined);
  } else {
    await client.rejectFinding(finding.id);
  }
}
```

Deciding is a `write`-bucket call, 120 per minute, so clearing a backlog is not constrained the way searching is. See [Limits](/locusgraph/client/limits).
