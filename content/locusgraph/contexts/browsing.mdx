# Browse

Searching finds memories. Browsing finds **contexts**: useful when you are building a UI over the graph, or checking what your naming has actually produced.

## What types exist

```typescript
const { context_types, total } = await client.listContextTypes("acme");
```

```typescript
[
  { context_type: "person", count: 42 },
  { context_type: "preference", count: 18 },
  { context_type: "project", count: 7 },
]
```

Run this after a week of writes. If you find both `preference` and `preferences`, you have two drawers for one idea and now is the cheapest time to know.

## What is in a type

```typescript
const { contexts } = await client.listContextsByType("preference", "acme", {
  page: 0,
  page_size: 50,
});
```

<Callout tone="trap" title="`page` starts at 0">
  Everywhere in the API. Asking for page `1` silently hands you the second page, no error, just a
  missing first row in your list.
</Callout>

## Searching by name

```typescript
const results = await client.searchContexts("alice", "acme", {
  context_type: "person",
  min_count: 2,
  include: "relationships",
  format: "json",
});
```

| Option | What it does |
| --- | --- |
| `context_type` | Restrict to one type |
| `min_count` | Only contexts with at least this many memories |
| `include` | `"relationships"` folds each match's links into the response |
| `format` | How those relationships render: `"json"` (default), `"mindmap"`, `"toon"` |
| `page`, `page_size` | Pagination |

`min_count` is the useful one for cleanup: contexts with a single memory are often typos or one-offs.

## One context, with its numbers

```typescript
const { context, stats } = await client.getContextDetails({
  graphId: "acme",
  contextType: "person",
  contextName: "alice",
});
```

The context's metadata, and its stats beside it. Worth reading before
[deleting](/locusgraph/remember/deleting) anything: it says how much hangs off the name.

## Walking relationships

```typescript
const { relationships } = await client.getContextRelationships({
  graphId: "acme",
  contextType: "person",
  contextName: "alice",
  linkType: "extends",
  direction: "outgoing",
});
```

`direction` is `"outgoing"`, `"incoming"` or `"both"`. Outgoing is what this context points at; incoming is what points at it.

Both matter. *What does Alice extend?* is outgoing. *Who works at Acme?* is incoming on `org:acme`.

## The whole graph

```typescript
const graph = await client.getContextGraph({
  graphId: "acme",
  contextType: "person",
  contextName: "alice",
});

const everything = await client.getFullContextGraph({ graphId: "acme" });
```

One is the neighbourhood around a context; the other is every node and edge. The second grows with the graph. Reach for it to draw a picture, not inside a request path.
