# Concepts

Five words, and the API stops being a list of methods.

<ConceptTree />

All five appear in a single write:

```typescript
await client.storeEvent({
  graph_id: "acme",                 // the graph  - an isolated memory space
  context_id: "person:alice",       // the context - type:slug, the handle
  event_kind: "fact",               // the kind    - what sort of memory
  source: "user",                   // the source  - who says so
  extends: ["org:acme"],            // a link      - to another context
  payload: { data: "Alice joined Acme" },   // the memory itself
});
```

## Graph

An isolated memory space, addressed by an id. Nothing in one graph is visible from another.

One per user, one per workspace, one per project: whichever is your unit of separation. If two tenants must never see each other's memories, they get two graphs.

## Context

A named anchor, written `type:slug`:

<SlugAnatomy />

The context is the stable handle. Memories come and go beneath it; the name stays put, which is what lets you address the same idea next week.

<Callout tone="trap" title="The slug is the filing location">
  `preference:dark_mode` and `preference:darkMode` are two different drawers, each half full. Keep slugs short and canonical, and decide the spelling once: nothing downstream will tell you the same idea landed in two places.
</Callout>

## Memory

Also called a **locus**. One thing that was learned, stored under one or more contexts.

You **store and search memories**. You **address them by context**. The relationship runs both ways:

- One context holds many memories: the same preference stated three times is three memories, and the repetition is signal
- One memory can sit under several contexts: what Alice said about the billing UI belongs to both `user:alice` and `project:billing_ui`

## Event kind

What sort of memory this is, stamped when you write it. It decides how the memory is treated later.

| Group | Kinds |
| --- | --- |
| Knowledge | `fact` · `knowledge` · `observation` · `learned` · `feedback` |
| Rules | `constraint` · `rule` · `constraint_violation` |
| Actions | `action` · `task` · `operation` · `execution` · `completed` |
| Decisions | `decision` · `choice` · `selection` · `determination` |
| Routine | `routine` · `heartbeat` · `status` |
| Noise | `noise` · `debug` · `log` |

`fact` is the everyday one. Anything in **Noise** is stored but kept out of ranking, which is the honest place to put a heartbeat you may want to audit and never want returned.

## Source

Where a memory came from. Every write is stamped with one, and the stamp is a trust ladder, the higher the source, the more weight the memory carries when two memories disagree.

<TrustLadder />

Stamp honestly. A guess recorded as `verified` outranks the correction that comes later, and nothing in the system can tell you it happened.
