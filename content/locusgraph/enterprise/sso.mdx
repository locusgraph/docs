# SSO and access

Two different questions, answered differently: how a **person** gets in, and how a **program** does.

## People sign in

Sign-in is OAuth. Social login is supported today, and LocusGraph is itself an **OAuth 2.1 issuer** — authorization code with PKCE, refresh tokens, and client credentials for machine callers.

That matters for an enterprise rollout: your own application can sit in front of LocusGraph and issue credentials through a standard flow, rather than distributing long-lived secrets by hand.

<Callout tone="note" title="Provider coverage is a conversation">
  Which identity providers are wired, and whether your directory is among them, is not something
  to read off a docs page. Ask.
</Callout>

## Programs authenticate with a key

An agent secret is a bearer token. It has no session, no refresh, and no user behind it — it is the credential your service holds.

```typescript
const client = new LocusGraphClient({
  agentSecret: process.env.LOCUSGRAPH_AGENT_SECRET,
  graphId: tenant.graphId,
});
```

See [API keys](/locusgraph/graphs/keys) for minting, scoping and revoking.

## The three permission levels

Granted to **accounts**, not to keys:

| Permission | Can |
| --- | --- |
| `read` | Search and read memories |
| `write` | Everything `read` can, plus storing and linking |
| `owner` | Everything, plus settings, permissions and transfer |

```bash
curl -X POST https://api.locusgraph.com/v1/graphs/permissions/$GRAPH_ID \
  -H "Authorization: Bearer $LOCUSGRAPH_AGENT_SECRET" \
  -d '{ "account_id": "…", "permission": "write" }'
```

Granting again with a different value changes it. Revoking is immediate. See [Access and transfer](/locusgraph/graphs/access).

## Where the line belongs

| Give a | To |
| --- | --- |
| **Permission** | A person, or an account that holds it for a long time |
| **Scoped key** | A program, per graph, named and separately revocable |

<Callout tone="trap" title="Do not hand a service an owner permission">
  It is quicker than minting a key and it removes every boundary that makes the key useful. Losing
  a scoped key costs one graph; losing owner access costs settings, permissions and transfer on
  everything that account can reach.
</Callout>

## Offboarding

Three things, and missing any one leaves a door open:

1. Revoke the account's permission on each graph
2. Revoke the keys that account minted — they do not expire with the person
3. Transfer ownership of any graph they owned, or it has no administrator
